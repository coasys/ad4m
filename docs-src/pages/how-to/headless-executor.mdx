# Run a headless executor

You want an executor on a server or in CI, without the desktop Launcher. The binary is `ad4m-executor`; the settings go in a JSON config file, the secrets in files only the service can read. For what the executor is and the flags at a glance, see [Run an executor](../start/run-an-executor.mdx); every flag and config key is in [Executor config](../reference/executor-config.mdx).

<Callout type="warning">
  Never pass a secret as a command-line argument or print it. A flag value is visible to every user on the host through `ps` and stays in shell history. Use the `AD4M_*_FILE` variables below.
</Callout>

## 1. Get the binaries

Each GitHub release carries the executor and the CLI client for Linux x64, macOS arm64 and Windows x64 (`.github/workflows/publish.yml`):

```bash
TAG=$(curl -s https://api.github.com/repos/coasys/ad4m/releases/latest | grep '"tag_name"' | sed 's/.*"tag_name": "//;s/".*//')
VERSION=${TAG#v}
curl -L -o ad4m-executor "https://github.com/coasys/ad4m/releases/download/${TAG}/ad4m-cli-executor-linux-${VERSION}-x64"
curl -L -o ad4m          "https://github.com/coasys/ad4m/releases/download/${TAG}/ad4m-cli-client-linux-${VERSION}-x64"
chmod +x ad4m-executor ad4m
```

On macOS the names end in `-macos-${VERSION}-aarch64`, on Windows in `-windows-${VERSION}-x64.exe`. To build from a checkout instead: `pnpm install && pnpm build-dapp && (cd core && pnpm install) && pnpm run build-deno-snapshot && (cd cli && cargo build --release)` puts both binaries in `target/release/`.

## 2. Initialize the data directory

```bash
./ad4m-executor init --data-path ~/.ad4m
# Successfully initialized AD4M executor!
```

`init` writes the network bootstrap seed (`mainnet_seed.seed`) and a version file into the directory. Without the seed file the executor starts without its runtime service, so run `init` before the first `run`, and again after every update to a new build (`rust-executor/src/init.rs`). `--network-bootstrap-seed <file>` uses another seed.

## 3. Write the config file and the secrets

```bash
install -d -m 0700 ~/.config/ad4m ~/.config/ad4m/secrets
cat > ~/.config/ad4m/executor-config.json <<EOF
{
  "app_data_path": "$HOME/.ad4m",
  "port": 12000,
  "hc_admin_port": 12001,
  "hc_app_port": 12002,
  "localhost": true,
  "run_dapp_server": false,
  "auto_permit_cap_requests": false,
  "mcp_enabled": false,
  "log_config": { "rust_executor": "info", "holochain": "warn" }
}
EOF
python3 -c 'import os,secrets,sys; fd=os.open(sys.argv[1], os.O_WRONLY|os.O_CREAT|os.O_EXCL, 0o600); os.write(fd, secrets.token_urlsafe(32).encode()); os.close(fd)' ~/.config/ad4m/secrets/admin-credential
python3 -c 'import os,secrets,sys; fd=os.open(sys.argv[1], os.O_WRONLY|os.O_CREAT|os.O_EXCL, 0o600); os.write(fd, secrets.token_urlsafe(32).encode()); os.close(fd)' ~/.config/ad4m/secrets/unlock-passphrase
```

The file uses the Launcher's key names and holds no secrets: an inline `admin_credential` or SMTP password, or an unknown key, fails the parse (`rust-executor/src/config_file.rs`). Pin the Holochain ports; unset, the executor takes the first free port from 2000 and 1337 at every start. A secret file that group or others can read is refused.

| Secret | Variable with the value | Variable with a file path |
|---|---|---|
| Admin credential (required) | `AD4M_ADMIN_CREDENTIAL` | `AD4M_ADMIN_CREDENTIAL_FILE` |
| Agent passphrase, to unlock at start | | `AD4M_UNLOCK_PASSPHRASE_FILE` |
| SMTP password (multi-user email) | `AD4M_SMTP_PASSWORD` | `AD4M_SMTP_PASSWORD_FILE` |

Check what `run` will start with, secrets shown as `"<redacted>"`:

```bash
AD4M_ADMIN_CREDENTIAL_FILE=~/.config/ad4m/secrets/admin-credential ./ad4m-executor config print --config ~/.config/ad4m/executor-config.json
```

Every flag of `run` also reads `AD4M_<FLAG>` (for example `--mcp-port` reads `AD4M_MCP_PORT`); a flag beats the variable, the variable beats the file (`cli/src/run_config.rs`). Without `--config`, `auto_permit_cap_requests` defaults to `true`; with one, to `false`.

## 4. Start it and create the agent

```bash
AD4M_ADMIN_CREDENTIAL_FILE=~/.config/ad4m/secrets/admin-credential \
AD4M_UNLOCK_PASSPHRASE_FILE=~/.config/ad4m/secrets/unlock-passphrase \
./ad4m-executor run --config ~/.config/ad4m/executor-config.json
```

The first start takes a couple of minutes (Holochain starts, the system languages install). On the first start only, create the agent with the passphrase from its file. The repository's helper reads both secrets from files and sends the credential only to a loopback address:

```bash
AD4M_URL=http://127.0.0.1:12000 \
AD4M_ADMIN_CREDENTIAL_FILE=~/.config/ad4m/secrets/admin-credential \
AD4M_UNLOCK_PASSPHRASE_FILE=~/.config/ad4m/secrets/unlock-passphrase \
node deploy/staging/agent.mjs generate
# generated did:key:z6Mk…
```

`deploy/staging/agent.mjs` needs Node 22 or later; `status` instead of `generate` prints `unlocked`, `locked` or `no-agent`. From then on every start unlocks the agent from `AD4M_UNLOCK_PASSPHRASE_FILE`. With the CLI client, `ad4m -a "$(cat ~/.config/ad4m/secrets/admin-credential)" -e http://127.0.0.1:12000 agent generate` does the same and prompts for the passphrase; the credential is then in that command's argument list while it runs.

## 5. Run it as a systemd user service

Install the binary under a release directory, so an update is a new directory and a rollback is a link: `install -D -m 0755 -t ~/.local/share/ad4m/releases/<version> ad4m-executor ad4m && ln -sfn releases/<version> ~/.local/share/ad4m/current`. Then:

```ini
# ~/.config/systemd/user/ad4m-executor.service
[Unit]
Description=AD4M executor (headless)
After=network-online.target
Wants=network-online.target
ConditionPathExists=%h/.local/share/ad4m/current/ad4m-executor

[Service]
Type=simple
WorkingDirectory=%h
LoadCredential=admin-credential:%h/.config/ad4m/secrets/admin-credential
LoadCredential=unlock-passphrase:%h/.config/ad4m/secrets/unlock-passphrase
Environment=AD4M_ADMIN_CREDENTIAL_FILE=%d/admin-credential
Environment=AD4M_UNLOCK_PASSPHRASE_FILE=%d/unlock-passphrase
Environment=MCP_HOST=127.0.0.1
ExecStart=%h/.local/share/ad4m/current/ad4m-executor run --config %h/.config/ad4m/executor-config.json
Restart=on-failure
RestartSec=10
TimeoutStopSec=60

[Install]
WantedBy=default.target
```

```bash
loginctl show-user "$USER" -p Linger      # Linger=yes, or as root: loginctl enable-linger <user>
systemctl --user daemon-reload && systemctl --user enable --now ad4m-executor.service
```

`LoadCredential=` copies each secret into a directory only this unit can read (`%d`), so no secret is in an environment block or argument list. `MCP_HOST=127.0.0.1` matters once MCP is on: with an admin credential set, the MCP server binds `0.0.0.0` unless told otherwise (`rust-executor/src/mcp/server.rs`). The repository runs its staging node with this unit (`deploy/staging/ad4m-staging.service`).

## 6. Check it

```bash
systemctl --user is-active ad4m-executor.service       # active
curl -fsS http://127.0.0.1:12000/health                # {"status":"ok"}
AD4M_URL=http://127.0.0.1:12000 AD4M_ADMIN_CREDENTIAL_FILE=~/.config/ad4m/secrets/admin-credential node deploy/staging/agent.mjs status   # unlocked
ss -ltnH '( sport = :12000 or sport = :12001 or sport = :12002 or sport = :3001 )'   # only 127.0.0.1 / [::1]
journalctl --user -u ad4m-executor -n 50 --no-pager
```

`/health` only shows the HTTP server is up; `status` shows the node is usable. `locked` means the passphrase file does not match the agent.

## Update and roll back

Stop the service, copy the data directory, point `current` at the new build, run `init`, start, check:

```bash
new=<version>    # installed under ~/.local/share/ad4m/releases/<version> as in step 5
old=$(readlink ~/.local/share/ad4m/current)
systemctl --user stop ad4m-executor.service \
  && cp -a --reflink=auto ~/.ad4m ~/.ad4m.pre-$new \
  && ln -sfn releases/$new ~/.local/share/ad4m/current \
  && ~/.local/share/ad4m/current/ad4m-executor init --data-path ~/.ad4m \
  && systemctl --user start ad4m-executor.service
```

The copy is what makes a rollback possible: a newer build may migrate the data so the old one cannot read it. To go back, stop the service, move `~/.ad4m` aside, copy `~/.ad4m.pre-$new` back, point `current` at `$old` and start; writes made since the update are lost. `deploy/staging/update.sh` automates this for a branch, with a test of its failure paths.

The admin credential can be rotated by replacing its file and restarting; tokens users got by logging in stay valid. The unlock passphrase encrypts the agent's keys and the executor has no call to change it: replacing the file makes every start fail to unlock.

## In Docker

The repository's `Dockerfile` builds an image with the executor, the CLI and, by default, the WE web app; no image is published, so build it yourself:

```bash
docker build -t ad4m-executor --build-arg INCLUDE_WE=false .
# ~/.config/ad4m/secrets/docker.env, mode 0600:
#   ADMIN_CREDENTIAL=<the admin credential>
#   AGENT_PASSPHRASE=<the agent passphrase>
docker run -d --name ad4m --env-file ~/.config/ad4m/secrets/docker.env \
  -v ad4m-data:/data -p 127.0.0.1:12000:12000 ad4m-executor
```

The entrypoint (`docker-entrypoint.sh`) refuses to start without `ADMIN_CREDENTIAL`, runs `init` on an empty `/data` with the image's seed of local bootstrap languages, generates the agent from `AGENT_PASSPHRASE` on the first boot and unlocks it on later ones, and runs `ad4m-executor run --app-data-path /data --localhost false --run-dapp-server false`. Other variables: `ENABLE_MULTI_USER=true`, `ENABLE_MCP=true` with `MCP_PORT` (default 3001), `RUN_HOLOCHAIN=true|false`, `NETWORK_BOOTSTRAP_SEED=<file>`. Build arguments: `INCLUDE_WE` (default `true`, serves WE and Flux through Caddy on port 8080) and `INCLUDE_MODELS` (default `false`, pre-caches the local AI models, about 1.8 GB). The executor listens on `0.0.0.0` inside the container, so publish its port to `127.0.0.1` unless a proxy or a multi-user setup is meant to reach it.

## Behind a reverse proxy

The RPC port speaks plain HTTP and WebSocket. To publish it over TLS without the executor's own TLS listener, terminate TLS in a proxy on the same machine and proxy to `127.0.0.1:12000` with the `Upgrade` and `Connection` headers passed through and a long read timeout (RPC sockets stay open). Set `X-Forwarded-For` and `X-Forwarded-Proto`, return 404 for `/internal/`, do not proxy the MCP port, and allow request bodies of at least 50 MB (the executor's limit for audio; 10 MB otherwise). At a smaller limit the proxy answers 413 without CORS headers, which a browser reports only as `Failed to fetch`. The repository's nginx vhost: `deploy/staging/nginx.conf.example`. To serve many users from it, see [Multi-user host](./multi-user-host.mdx).

## Moving a node off the Launcher

The Launcher runs the same executor and keeps its settings in `~/.ad4m/launcher-state.json` under the same key names. Write the config file from it (`app_data_path` of the selected agent, `port`, `multi_user_config` with `password_file` in place of an SMTP password, `mcp_enabled`, `mcp_port`, `run_dapp_server`, `log_config`), put the agent's existing passphrase into the unlock-passphrase file, quit the Launcher, copy the data directory, and start the service with a build of the same version the Launcher ran, so no migration happens during the switch.

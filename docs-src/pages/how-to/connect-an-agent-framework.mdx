# Connect an agent framework

Prerequisite: the executor's MCP server is enabled ([Run the MCP server](./mcp-server.mdx)); default endpoint `http://localhost:3001/mcp`.

## OpenClaw: the AD4M plugin

The plugin lives in this repository under `plugins/ad4m`. It bridges the executor's MCP tools into the agent's tool list under an `ad4m_` prefix (`ad4m_describe_perspective`, `ad4m_instance_create`, …), and adds tools of its own for wakers: `ad4m_subscribe_to_mentions(perspective_id)`, `ad4m_subscribe_to_children(perspective_id, expression_address)`, the matching `ad4m_unsubscribe_from_*`, and `ad4m_list_waker_subscriptions()`. A waker registers a SPARQL subscription over the executor's WebSocket API and wakes the agent when matching links appear; joining or publishing a neighbourhood subscribes to mentions automatically.

Setup is one command, which detects the situation and prints the config to paste:

```bash
openclaw plugins install @coasys/openclaw-ad4m   # or the .tgz path
openclaw ad4m-setup
```

- **Managed mode** (no executor running): the plugin starts `ad4m-executor` itself, generates the agent and unlocks it on every start.
- **External mode** (an executor already running, for example the Launcher): the plugin calls `request_capability`, you approve the request in the Launcher and enter the six-digit code, and setup prints a config with the resulting JWT.

```json5
{
  plugins: {
    entries: {
      "ad4m": {
        enabled: true,
        config: {
          "mode": "external",
          "token": "eyJhbGciOi...",            // JWT from setup
          "executorUrl": "http://localhost:12000",
          "mcpEndpoint": "http://localhost:3001/mcp"
        }
      }
    }
  }
}
```

The other fields (`agentPassphrase`, `wakeUrl`, `debounceMs`, `multiUser`/`email`/`password` for a hosted node, `allowInsecureHttp` for a non-loopback plaintext endpoint) are documented in `plugins/ad4m/README.md`. Restart the OpenClaw gateway after changing the config; plugins load at start.

## Claude

Claude Desktop and Claude Code read an `mcpServers` map. Give it the endpoint and, when the executor has an admin credential or you hold a JWT, an `Authorization` header:

```json
{
  "mcpServers": {
    "ad4m": {
      "type": "http",
      "url": "http://localhost:3001/mcp",
      "headers": { "Authorization": "Bearer <admin credential or JWT>" }
    }
  }
}
```

Without a header on a node that has no admin credential, every call from loopback is accepted as the node's owner. Without a header on a node that has one, authenticate inside the session: `request_capability` then `generate_jwt`, or `login_email` on a hosted node.

<Callout type="info">
A header-only client never stores a session token, so `auth_status` keeps answering `authenticated: false` while every other call succeeds. The first protected call that carries the header adopts it into the session.
</Callout>

## Any other MCP client

The endpoint is standard Streamable HTTP. Configure the URL and the header as above; then call `get_documentation(topic="overview")` first, which the executor compiles in from its own sources ([overview](../reference/mcp-topics/overview.md)).

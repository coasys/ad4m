# Portability contract for `docs-src/pages`

The pages under `docs-src/pages` are written so that a different site shell
(the planned Coasys docs site, Astro Starlight or Docusaurus) can import them
unchanged. Nextra is the current shell; nothing in a page may depend on it
beyond the component set listed here. `scripts/check-portability.mjs` enforces
the rules below and runs in CI (`.github/workflows/docs.yml`) and as part of
`pnpm run build`.

## Rules for a content page

1. **Format.** `.mdx` (or `.md`) with YAML frontmatter. `title` and
   `description` are required; `description` is one sentence used for the
   page's `<meta name="description">` and for search snippets.

   ```mdx
   ---
   title: Queries and live results
   description: Model queries, SPARQL, subscriptions, and how verified links are filtered.
   ---
   ```

2. **Links between pages are file-relative and carry the extension.**
   `[Perspectives](../concepts/perspectives-and-links.mdx)`,
   `[Queries](./queries.mdx#where-operators)`. The shell maps a file path to
   a URL (Nextra: a remark plugin in `next.config.js`; Docusaurus: native;
   Starlight: the import step rewrites them). Site-absolute (`/concepts/...`)
   and extension-less relative links are rejected, because the three shells
   disagree on the URL prefix and on trailing slashes. Links to the generated
   API reference use the `/jsdoc/...` prefix and are the one exception: that
   tree is generated by typedoc per shell.

3. **Images live next to the page** (or in a sibling `images/` directory) and
   are referenced relatively: `![The spanning layer](./images/spanning-layer.png)`.
   Nothing under `public/` is referenced from a page. Images in `public/` are
   only for the shell (favicon, OG card, logo).

4. **Components.** The only imports allowed in a page are:

   ```mdx
   import { Callout, Tabs, Tab } from "nextra/components";
   ```

   | Component | Use | Nextra 2 | Astro Starlight | Docusaurus |
   |---|---|---|---|---|
   | `Callout` | `<Callout type="info|warning|error">` short note | `nextra/components` | `<Aside type="note|caution|danger">` from `@astrojs/starlight/components` | `:::note` / `:::warning` / `:::danger` admonitions |
   | `Tabs` + `Tab` | `<Tabs items={["TypeScript", "SHACL"]}><Tab>…</Tab></Tabs>` | `nextra/components` | `<Tabs><TabItem label="TypeScript">…</TabItem></Tabs>` from `@astrojs/starlight/components` | `<Tabs><TabItem value="ts" label="TypeScript">` from `@theme/Tabs` |

   Every other `import` or `export` in a page fails the check. `import`
   statements inside fenced code blocks are code samples and are ignored by
   the check. Raw HTML is limited to `<details>`, `<summary>`, `<br>`, `<img>`
   (relative `src`), `<sup>`, `<sub>`, `<kbd>`.

5. **No shell-specific features.** No `_meta.json` references inside pages, no
   Next.js `Link`/`Image`, no React hooks, no `theme.config` access, no
   `{/* */}` relying on Nextra behaviour, no front-matter keys other than
   `title`, `description`, `sidebar_label` (optional, shorter nav label),
   `draft` (optional, `true` hides from nav).

6. **One kind of page.** Each file is a tutorial step, a concept, a how-to or
   a reference page, and sits in the matching directory (`tutorial/`,
   `concepts/`, `how-to/`, `reference/`; `start/` holds the three entrance
   quickstarts). The landing page is `index.mdx`.

7. **Navigation metadata** (`_meta.json`) is shell-specific and is not part
   of the portable content. The import manifest below carries the order.

8. **Generated content** is not hand-edited: `reference/mcp-topics/*.md` is
   copied from `rust-executor/src/mcp/docs/` by `scripts/copy-mcp-topics.mjs`
   at build time (gitignored); `pages/jsdoc/` is typedoc output.

## Redirects

`redirects.json` maps every route that existed before 2026-10-21 to its new
file, with a map of old section anchors to new `file#anchor` targets. The
Nextra build writes a redirect page at each old route from it
(`scripts/write-redirects.mjs`). The same file feeds the domain move later:
`docs.ad4m.dev/<old>` → `docs.coasys.org/ad4m/<new>`.

```json
{
  "redirects": {
    "/developer-guides/model-classes": {
      "to": "concepts/models-and-identity.mdx",
      "anchors": {
        "querying": "concepts/queries.mdx",
        "abstract-classes": "concepts/abstract-classes-and-aliases.mdx#abstract-classes"
      }
    }
  }
}
```

## Import manifest (sketch for the Coasys docs shell)

The shell builds from pinned revisions and never reads "whatever `dev` is".
Each product repo ships a manifest at `docs-src/manifest.json`; the shell
reads it at the pinned SHA:

```json
{
  "product": "ad4m",
  "section": "/ad4m",
  "title": "AD4M",
  "contentRoot": "docs-src/pages",
  "include": ["index.mdx", "start/**", "tutorial/**", "concepts/**", "how-to/**", "reference/**"],
  "exclude": ["jsdoc/**", "reference/mcp-topics/**"],
  "generated": [
    { "kind": "typedoc", "entry": "core/src/index.ts", "route": "reference/sdk" },
    { "kind": "copy", "from": "rust-executor/src/mcp/docs/*.md", "route": "reference/mcp-topics" }
  ],
  "nav": [
    { "label": "Start", "dir": "start", "order": ["build-an-app", "connect-an-agent", "run-an-executor"] },
    { "label": "Tutorial", "dir": "tutorial" },
    { "label": "Concepts", "dir": "concepts", "order": ["what-ad4m-is", "..."] },
    { "label": "How-to", "dir": "how-to" },
    { "label": "Reference", "dir": "reference" }
  ],
  "components": { "Callout": "nextra/components", "Tabs": "nextra/components", "Tab": "nextra/components" },
  "redirects": "docs-src/redirects.json",
  "editBase": "https://github.com/coasys/ad4m/blob/{sha}/docs-src/pages/"
}
```

What the shell does with it: copies `include` minus `exclude` under
`section`, rewrites file-relative `.mdx` links to the shell's URL scheme,
copies images beside their pages, replaces the three components by the
shell's equivalents from the table above, runs the generators, writes the
redirect pages, builds the sidebar from `nav` (falling back to file order),
and records `{shell SHA, ad4m SHA}` on the deployed site. The manifest file
itself is not yet written; this sketch is the contract for it.

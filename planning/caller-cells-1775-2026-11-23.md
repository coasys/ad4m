# ad4m#1775 — language calls run as the caller; one Holochain cell per user

Scope (Nico, 17 Nov): one shared language instance per address, no per-user
runtimes. (1) Every language call runs as the caller's agent. (2) A Holochain
cell per user for agent-keyed DNAs. System languages stay shared.

Three PRs (Nico, 23 Nov):

- **A = #1101** (per-language Holochain agent key, #1099), rebased on #1861.
- **B = this branch**: the generic executor part, on top of A. No Acorn code.
- **C = the Acorn stack runs as the caller**: `acorn/pr5-instance-writes` + B,
  then call actions, mounts and mount deltas act as the caller / owner.

## What #1861 and #1101 already give

- #1861: every call into a language carries a `CallAgent` token (cppgc object,
  not forgeable from JS) in a V8 async-context variable. The `AGENT.*` ops act
  as it, so `agentDid()` in a language answers the agent of the current call.
  Host entries (init, callbacks, teardown, module evaluation, signals) run as
  the main agent.
- #1101: the main agent's Holochain key is per language
  (`agent_key_for_language`): stored mapping -> adopt the installed app's key ->
  fresh lair key, persisted, under a per-language lock.

## The key / cell model (B)

- **Main agent: unchanged.** #1101's key, the same app ids
  (`<lang>-<nick>`), the same cells and signal routes. No migration.
- **Managed user U in language L**: `HolochainServiceInterface::agent_key_for(L,
  AgentContext, app_id)` generalises #1101's resolution from (language) to
  (language, agent): the same order and lock, setting
  `language_agent_key:<L>:<U-did>` (the main agent keeps
  `language_agent_key:<L>`). One key per (language, user), so two languages
  with the same DNA + seed never collide on one cell (#1099).
- **User app** `<main app id>@<U-did>`: installed lazily on U's first
  Holochain call in L with the main install's payload (same bundle, same
  `network_seed` => same DNA hash => same network and DHT) but
  `agent_key = K(L, U)`. A per-(app, user) lock: two concurrent first calls
  install once. Acorn projects are templated languages with their own
  `network_seed`; each project's per-user app follows the same rule.
- `holochain_service/user_cells.rs` (`UserCells`) holds the routing behind a
  `CellBackend` trait (app info, install, key resolution, settings), so it is
  tested without a conductor:
  - `remember_main_app(app_id, language, payload)` — the `install_app` op,
    before installing (after a restart the install fails as "already
    installed", the users still need the payload). Only an app id of the
    language's own (`<address>-...`).
  - `app_for_call(app_id, language, agent)` — main agent / system language:
    `app_id`; user: the user's app, installed on first use. A user call to an
    app its language did not register is refused (it would reach the main
    agent's or another language's cell); so is naming another user's app.
  - `route_for_cell(cell_key)` — user cells' signal routes;
    `restore_user_routes` brings them back after a restart (users per language
    are stored in `language_agent_users:<L>`).
  - System languages (`load_language(.., is_system_language = true)`) never get
    user cells.

## The caller travels into every Holochain op (B)

- `agent_extension.js` exposes `__ad4mCallAgent()` (non-writable): the current
  call's token. `HOLOCHAIN_SERVICE.installApp / getAppInfo / callZomeFunction`
  hand it to their ops (`#[cppgc] Option<&CallAgent>`).
- No token (executor JS, code that cleared its async context) = main agent:
  the routing every op had before, so nothing that ran before changes cell.
- `install_app` as a user: the main install if needed, then the user's app.
  `get_app_info` as a user: the user's app info (lazy install); `None` for an
  app no language registered. `call_zome_function`: the app id mapped through
  `app_for_call`, then the call as today (provenance = the app's agent key).
- Signal loop (`lib.rs`): a user cell's signal goes to the language with
  `AgentContext::managed(did)`; other cells as before (main agent).
- `language_bootstrap.js`: delegate `appInfo(nick)` (the caller's AppInfo);
  `ad4m:host` exports `holochainAppInfo(nick)`. A legacy signal callback
  registered for a DNA's main cell also serves that DNA's user cells.
- `expression_interact(url, call, &AgentContext)`; `expression.interact`
  passes the request's `acts_as()`. Internal callers pass the main agent.

## Link languages stay on the main agent

Every `Language` method of a link language (commit, sync, render,
currentRevision, others, telepresence) passes `AgentContext::main_agent()`
(`languages/language.rs`), and their signals come from main cells. Link
languages are loaded as system languages, and `app_for_call` keeps system
languages on the main app whatever the caller. So neighbourhoods keep their
DHT agent and history: moving one to a per-user cell would change both.

## C: the Acorn stack runs as the caller

- Call actions pass the writer's context to `expression_interact`;
  `check_call_caller` keeps only the `expression:update` rule.
- mount / syncMount / resync run `mountShapes`/`mountSnapshot` as the
  perspective's owner (`PerspectiveHandle` primary owner; the main agent when
  it has none or it is the main DID).
- `ad4m_signal_emitted` takes the call's token; a `mountDelta` goes only to
  the perspectives the emitting agent owns.
- `refuse_mount_for_users` removed.

## Risks

- Language code is not isolated per agent (#1861, SEC-4): code that saves an
  async context can act as another user — now also for zome calls.
- First Holochain call of a user in a language installs an app: up to
  `APP_INSTALL_TIMEOUT_DURATION` (45 s) on a cold node, usually a few s.
- One cell per (user, language that holds a DNA): its own source chain DB and
  network join.
- `get_agent_key()` (JS `getAgentKey`) still answers lair's first key, not the
  caller's.
